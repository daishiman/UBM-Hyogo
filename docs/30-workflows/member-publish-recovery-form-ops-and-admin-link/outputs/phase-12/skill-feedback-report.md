# スキルフィードバックレポート

## 1. テンプレート改善

- 「backend は実装済みだが UI 導線が無い」型タスクの判定知見: 事前調査で endpoint/route の実在を確認した結果、
  新規バックエンド契約を 0 に近づけ「UI wiring + docs」へ再スコープできた。CONST_004 の実装区分判定で
  「目的達成にコード変更が必要か」を endpoint 実在ベースで先に切り分けると、過剰実装を避けつつ実装仕様書化できる。

## 2. ワークフロー改善

- 責務分離タスク（A/B/C/D）の並列 SubAgent 作成で、Task B が A の前提（proxy 認証経路）の盲点を発見した。
  並列作成は横断的前提の発見に有効。発見後は親 phase-9（共通課題）と該当タスク（A）へクロスリファレンスを
  同一 wave で反映し、仕様セット全体の整合を保つ運用が有効だった。
- 同一ファイル（`sync-status/page.tsx`）を複数タスクが編集する場合、パネルを別 client component に分離する設計を
  仕様段階で確定しておくと、実装時の並列編集競合を避けられる。

## 3. ドキュメント改善

- 反映 SLA（cron `*/15` / ISR 30s / 最悪 15-45 分）が `03-data-fetching.md` に欠落していた。
  ユーザー質問「何分で反映されるか」は doc 化対象であり、Task C で恒久回答化する。
