## 1. テンプレート改善（task-specification-creator）

| 項目 | 内容 |
| --- | --- |
| 改善提案 | **なし** |
| 知見（記録のみ） | 単一 write と bulk write で **同一 payload キー（`batchId`）を共有** する場合、相関の「まとまり」粒度（リクエスト単位 vs セッション単位）を **Phase 1 で先に固定** しないと payload 設計が振れる。本タスクでは Phase 1「真の論点」で「相関の単位を先に固定する」を主問題として明示し、request-scoped（群サイズ 1）に確定したことで Phase 2 以降の payload 設計（生成箇所・配置・命名）が一意に決まった。粒度未固定のまま payload 着手すると、後段で「セッション単位にすべきだったか」の手戻りが発生しうる。 |

> 提案: payload に correlation/batch 系キーを足すタスクでは、Phase 1 テンプレに
> 「相関のまとまり粒度（request / session / transaction）を先に固定する」確認項目を置くと振れを防げる
> （本タスクは既存テンプレの「真の論点」枠で吸収できたため、即時のテンプレ改修は不要）。
