## 目的

Phase 1 で固定した AC-1〜AC-11 が、Phase 4 の正常系 TC-01〜TC-10 と Phase 6 の異常系 TC-E01〜TC-E05 でそれぞれ最低 1 件以上カバーされていることを、カバレッジマトリクス（縦 AC × 横 TC）で検証する。テストで自動検証できない AC（read-only=AC-7・4 条件=AC-11）はコードレビュー観点で担保する旨を明記し、カバレッジ欠落（穴）が無いことを確定する。

## テスト非対象 AC の担保方針

| AC | テストで担保できない理由 | 担保手段 |
| --- | --- | --- |
| AC-7（read-only） | 「書き込み / ネットワークを行わない」の不在証明はユニットテスト単体では完全には示せない | TC-E01 で例外時も書き込まないことを確認しつつ、**コードレビュー観点**で `readFileSync` のみ・`writeFileSync`/`fetch`/`child_process` 不在を確認（D-7） |
| AC-9（CI workflow 配線） | workflow の `paths:` トリガと permissions は spec test の対象外 | Phase 5 変更ファイルレビュー + 既存 `verify-design-tokens.yml` との規約整合をコードレビューで担保。実起動は PR の CI run で確認 |
| AC-11（4 条件 PASS） | プロセス評価でありコード挙動ではない | Phase 1 / Phase 3 の 4 条件評価（全 PASS）で担保済み。本マトリクスは整合確認のみ |

## カバレッジ穴の確認

- AC-1〜AC-6・AC-10 はいずれも 1 件以上の `●`（主担保 TC）を持つ → **穴なし**。
- AC-7 / AC-9 / AC-11 はコードレビュー / プロセス担保（上表）→ **穴なし（担保手段明示）**。
- 異常系 TC-E01〜TC-E05 は AC-1 / AC-3 / AC-4 / AC-7 を補強し、誤 fail / 誤 pass の境界を埋める。
