# Phase 3 — 検討した代替案と不採用理由

> change-map（採用案 = 完全日本語化 + 軽微 CSS）に至る前に検討した代替案を記録する。

---

## 代替案 A: 英語併記案（日英 2 段表記）

**内容**: 見出しを `全体の状況（PRIMARY）` のように日英併記し、英語キーワードを残す。

| 観点 | 評価 |
| --- | --- |
| 価値性 | △ ユーザー Q1 で「英語は残さない（完全置換）」を確定済み。併記は要件と矛盾 |
| 認知負荷 | × 非エンジニアにとって英語は雑音。併記はかえって読む量が増える |
| 一貫性 | × 一部だけ併記すると、どこに英語が残るかで判断がぶれる |

**不採用理由**: ユーザー確定事項（Q1 = 完全日本語化）に反する。非エンジニア向けという目的にも逆行する。

---

## 代替案 B: 構造再設計案（ゾーン作り替え・カード再配置）

**内容**: 文言だけでなく 3 ゾーン構造（PRIMARY / TREND / DETAIL）自体を作り替え、カード配置やチャート表現も刷新して「見やすさ」を抜本改善する。

| 観点 | 評価 |
| --- | --- |
| スコープ | × 1 サイクル（CONST_007）に収まらない。テスト / Playwright / visual baseline の大規模再取得が必要 |
| ユーザー意向 | × Q3 で「ラベル平易化 ＋ 見やすさ微調整（新規 primitive なし・大規模再設計なし）」を確定済み |
| リスク | × DOM contract（testid / role）破壊で既存テスト全面書き換え。回帰リスク大 |
| 直前タスクとの整合 | × 3 ゾーン階層化は `completed-tasks/admin-attendance-dashboard-ux-hierarchy-refine` で landed 済み。これを覆すのは二重投資 |

**不採用理由**: ユーザー確定（Q3 = 微調整）とスコープ制約（CONST_007）に反する。3 ゾーン骨格は landed 済みの資産であり、本タスクはその上に文言の日本語化を重ねる独立タスクとして設計する。

---

## 代替案 C: 共通用語集 SSOT を新設する案

**内容**: リネーム文言を `attendanceGlossary.ts` のような新規 SSOT モジュールに集約し、各 component から参照する。

| 観点 | 評価 |
| --- | --- |
| 保守性 | ○ 将来の用語統一には有効 |
| スコープ | × 新規モジュール = 実質「新規 util 追加」。AC-6（新規追加ゼロ）と矛盾。参照差し替えで diff が膨らみ 1 サイクル超過リスク |
| 必要性 | × 本タスクは一度きりの文言置換。文言は各 component に直書きで十分（既存も直書き） |

**不採用理由**: 本タスクの文言は静的で再利用頻度が低く、SSOT 化の便益よりも新規追加コスト・AC-6 抵触リスクが上回る。既存の直書きスタイルを踏襲し、文字列を置換するのみとする。

---
