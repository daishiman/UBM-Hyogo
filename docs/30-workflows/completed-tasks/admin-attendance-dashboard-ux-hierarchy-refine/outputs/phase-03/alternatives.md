# Phase 3 — alternatives（代替案とトレードオフ）

> 上流: `../phase-02/*`。検討した代替案・却下理由・採用根拠を記録する。

## 軸 1: 再構成アプローチ

### 案 A（採用）: 階層リファイン（8 セクション維持 + 3 層再配置）

- **構造**: 既存 8 セクションを情報優先順位で PRIMARY / TREND / DETAIL の 3 層に再配置。データ取得・型は不変。
- **メリット**:
  - 機能を欠落させず「情報過多」だけを解消（AC-10 温存）
  - 既存 primitive + token + endpoint で 1 サイクル完了（実現性◎）
  - 表現層に閉じ AC-7（API/D1/shared 不変）を自然に満たす
- **デメリット**:
  - `AttendanceAnalyticsPage` の統括組み替えが必要
  - globals.css にゾーンクラス追加

### 案 B: 全面再構成（情報設計から作り直し・新コンポーネント群）

- **構造**: 既存コンポーネントを破棄し、ダッシュボード専用の新レイアウトシステムを構築。
- **メリット**: 設計自由度が最大。
- **デメリット**:
  - 既存機能の取りこぼしリスク大（AC-10 違反リスク）
  - 新規 primitive を生やしたくなる誘惑（AC-6 違反リスク）
  - 1 サイクルに収まらず実現性が低下
  - ユーザー確定方針（階層リファイン）と不一致
- **却下理由**: 価値に対しコスト過大。ユーザー方針違反。AC-6/AC-10 リスク。

### 案 C: 最小限調整（余白・色だけ微調整）

- **構造**: レイアウト構造は 8 セクション縦積みのまま、余白とタイポだけ整える。
- **メリット**: 最小コスト・最小リスク。
- **デメリット**:
  - 「パッと見て何を判断すべきか分からない」という主問題（情報階層の不在）が未解決
  - 焦点（出席率特大 / 要フォロー強調）が生まれない
- **却下理由**: 主問題（hierarchy/focal point の不在）を解消できない。価値性 NG。

## 軸 2: DETAIL ゾーンの開示方式

### 案 A（採用）: Segmented タブ（排他 1 表示）

- **メリット**:
  - 既存 `Segmented` primitive 再利用（AC-6）
  - 排他表示で初期スクロール削減（AC-3）
  - `role="radiogroup"` / `aria-checked` の a11y を既存実装で担保（AC-9）
  - internal `useState` で状態が単純（[VSCPKR-03]）
- **デメリット**: 一度に 1 表しか見えない（横断比較に 1 クリック必要）

### 案 D: アコーディオン（複数同時展開可）

- **メリット**: 複数表を同時に開いて比較できる。
- **デメリット**:
  - 既存に該当 primitive がなく新規実装が必要（AC-6 違反リスク）
  - 全展開すると縦積みと同じ「情報過多」に逆戻り（主問題再発）
  - 開閉状態が複数 boolean になり状態が複雑化
- **却下理由**: AC-6 リスク + 主問題（情報過多）再発。

| 軸 2 比較 | 案 A タブ（採用） | 案 D アコーディオン |
| --- | --- | --- |
| AC-6（新規 primitive ゼロ） | ◎ | ✗ |
| AC-3（スクロール削減） | ◎ | △（全展開で逆戻り） |
| AC-9（a11y） | ◎（既存 radiogroup） | △（新規実装） |
| 状態の単純さ | ◎（単一 state） | △（複数 boolean） |
| 採否 | **採用** | 却下 |

## 軸 3: PRIMARY ヒーローの構成

### 案 A（採用）: 2 枚ヒーロー（出席率 + 要フォロー）

- **メリット**:
  - ユーザーが最重要として選んだ 4 項目のうち、判断アクションに直結する 2 つ（健全性 = 出席率 / 対応 = 要フォロー）を昇格
  - 出席率は「状態把握」、要フォローは「即アクション」で役割が補完的
- **デメリット**: 残り 2 項目（推移 / 偏り）は TREND へ降格

### 案 E: 単一 KPI ヒーロー（出席率のみ特大）

- **メリット**: 最も焦点が 1 点に絞られる。
- **デメリット**:
  - ユーザーが「要フォロー対象」も最重要と明示 → 単一だと要フォローが埋もれる
  - 「状態把握」だけで「アクション」への導線が弱い
- **却下理由**: ユーザーの最重要選択（要フォロー含む）と不一致。アクション導線不足。

| 軸 3 比較 | 案 A 2 枚（採用） | 案 E 単一 |
| --- | --- | --- |
| ユーザー最重要選択の反映 | ◎（出席率 + 要フォロー） | △（出席率のみ） |
| アクション導線 | ◎（要フォロー hero） | ✗ |
| 焦点の絞り込み | ○（2 点） | ◎（1 点） |
| AC-1 適合 | ◎ | △ |
| 採否 | **採用** | 却下 |

## 総括: なぜ「階層リファイン + Segmented タブ + 2 枚ヒーロー」か

1. **階層リファイン**（軸 1-A）: ユーザー確定方針に整合し、機能を欠落させず主問題（階層不在）を解消。AC-6/AC-7/AC-10 を自然に満たす。
2. **Segmented タブ**（軸 2-A）: 既存 primitive 再利用で AC-6 を守りつつ、排他表示で AC-3（スクロール削減）と AC-9（a11y）を両立。アコーディオンの「情報過多再発」を回避。
3. **2 枚ヒーロー**（軸 3-A）: ユーザーが最重要とした出席率 + 要フォローを昇格し、「状態把握 + 即アクション」の補完構造で AC-1 を満たす。

3 軸とも採用案がデータ層・型に触れず（AC-7）、新規 primitive を生やさず（AC-6）、1 サイクルで実現可能（実現性◎）。MAJOR blocker なし。
