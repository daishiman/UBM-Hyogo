## 3. 真の論点の確認

- **現象**: 折りたたみ時アイコンの縦間隔が広い。
- **主問題（1文）**: 折りたたみ時アイコンコンテナ `h-10`(40px) が固定 18px グリフに対し過大な縦余白を生み、`py-2` と合わさり行ピッチが展開時より約 20px 大きい。
- **why now**: staging 実機でユーザーが体感し報告。
- **why this way**: グリフ非依存（固定 18px）が確認できたため、box 高の縮小がグリフを縮めずに余白だけ詰める最小・無害な手段。

## 4. 因果ループ確認

- バランスループ: box 高 ↓ → 行ピッチ ↓ → 展開時ピッチに収束（目標 36px 付近で安定）。
- 強化ループ（負の側面）: box 高を下げすぎる → タップ高 < 24px の懸念。→ 対策: 18〜20px（py-2 込みで 34〜36px タップ高）に下限を固定し WCAG 2.5.8 を満たす。

## 5. 責務境界 / 意思決定権

- verify fail（screenshot でピッチ不一致）時の意思決定権は実装者（Phase 5/11）。`h-[18px]` で不足なら `h-5`(20px) へ昇格する判断余地を Phase 5 に明記済み。
- 状態遷移の所有権は `useSidebarState`（不変）。本変更は描画値のみ。

## 6. 価値とコストの均衡

- 最高コスト部品: なし（CSS のみ）。将来拡張（Brand/Avatar 統一）は初回価値と混同せず OOS として分離。
