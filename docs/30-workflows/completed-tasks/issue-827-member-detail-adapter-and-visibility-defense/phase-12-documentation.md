# Phase 12: ドキュメント（中学生レベル概念説明）

## このタスクは何をする？

会員ページのプロフィール画面に「公開してよい情報だけ」を確実に出すための、**安全装置**を作るタスクです。

## なぜ必要？

会員ページの裏側（サーバー）は、すでに「みんなに見せていい情報」と「自分だけ・運営だけが見ていい情報」を分けて返してくれます。
でも、もしサーバーがバグで誤って「内緒の情報」を送ってきたら、画面にそのまま出てしまいます。

そこで「画面に出す直前」にも、もう一回チェック係を置きます。これが **二重防御 (double defense)** です。
銀行のドアが二重ロックになっているのと同じ考え方です。

## 主な概念

### Adapter（アダプタ）

「変換係」のこと。
サーバーから届いたデータをそのまま画面に渡すと、画面側のコードがゴチャゴチャします。
そこで「**画面に渡す前にちょうど良い形に整える専用の場所**」を作ります。これが adapter です。

例: 「全部の情報」→ adapter → 「画面に出していい情報だけ」

### Pure Function（純粋関数）

「同じ材料を入れたら必ず同じ料理が出てくる」関数のこと。
- 外の状態を変えない（mutation しない）
- 副作用を起こさない（ファイルに書かない、ネットワークを叩かない）

テストがとても楽になります。

### Visibility（公開範囲）

各情報には「誰に見せていいか」のラベルがついています:
- `public` — みんなに見せていい
- `member` — 会員だけ
- `admin` — 運営だけ

今回は `public` だけを画面に出します。

### Silent Skip（黙って飛ばす）

未知の種類のデータが来ても「エラーで画面が壊れる」のではなく「**そっと無視する**」こと。
将来サーバーが新しい種類のデータを送ってきても、画面が落ちないようにします。

## 全体の流れ

```
サーバー API (publicのみ返す)
      ↓
ページのコンポーネント (page.tsx)
      ↓
Adapter (もう一回 public だけに絞る) ← 今回作るところ
      ↓
画面パーツ (MemberDetailSections など)
      ↓
ブラウザに表示
```

## やらないこと

- データベースを直接いじる → やらない
- サーバー API を変える → やらない
- 画面のデザインを変える → やらない（render 結果は今と完全に同じになる予定）
