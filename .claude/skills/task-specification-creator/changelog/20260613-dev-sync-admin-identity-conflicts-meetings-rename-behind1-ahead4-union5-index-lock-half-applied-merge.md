- **🔴新規 L-DEVSYNC-142（`Unable to write index` = stale index.lock の半適用マージ診断）**: 最初の `git merge dev --no-edit` が `error: Unable to write index.` → `Automatic merge failed; fix conflicts and then commit the result.` で終了。だが `git status` は「All conflicts fixed but you are still merging（use git commit to conclude merge）」と表示する一方で **`git diff --cached --stat` が空・`git diff --diff-filter=U` も空・`MERGE_HEAD` は存在**という矛盾状態。worktree-local の `.git/worktrees/task-20260611-132318-wt-11/index.lock` に **0 byte の stale lock**（先行 git op が異常終了して残した残骸・mtime はマージ直前）が残っており、merge ツリー計算は成功したが index 反映段で lock に阻まれ**半適用で停止**していた。
  - 危険性: この半適用 MERGE_HEAD を信じて `git commit` すると**取込内容ゼロの空マージ commit** ができ、dev デルタ（#1220）が丸ごと落ちる。正常 auto-merge なら staged に取込差分が並び、正常 conflict なら `--diff-filter=U` に UU が並ぶので、**両方空＝壊れた中間状態**と矛盾シグナルで確定診断する。
  - 復旧: (1) `LOCK="$(git rev-parse --git-dir)/index.lock"`（worktree では `.git/worktrees/<name>/index.lock` に解決）を 0 byte / 自分のマージ直前 mtime と確認の上 `node -e "require('fs').unlinkSync(...)"` で原子削除（`rm` は権限プロンプト誘発を避ける） → (2) `git merge --abort` で半適用 index を破棄 → (3) `git merge dev` 再実行で本来の **CONFLICT 5 件**（`indexes/keywords.json` + `indexes/quick-reference.md` + `indexes/resource-map.md` + `indexes/topic-map.md` + `references/task-workflow-active.md`）が正しく顕在化。lock 削除だけで `git commit` してはいけない（半適用 index は壊れたまま）。
