- **運用ルールの是正（最重要）**: sync-merge 後に「CI fail 0」を主張する条件を厳格化する。**両ブランチが feature コード領域（同一 .ts ファイル等）を touch する場合、`git merge` の conflict 0 + typecheck + lint の緑は『CI 緑』の十分条件ではない**。意味的コンフリクト（disjoint-line auto-merge による同一挙動の二重実装）は textual merge にも型検査にも現れず、**影響を受ける test スイート（最低でも touch した package の `test:coverage` shard）をローカル実行するか、push 後に `gh pr checks` を確認するまで「CI fail 0」を確定しない**。1st pass はこの実行を省いて typecheck/lint/indexes 緑だけで「CI fail 0」と断定したのが誤りだった。**feature 側 skill 非 touch（skill index conflict 0）の事実自体は正しい**が、それは skill index 層の話であって **feature コード層の意味的安全とは独立**。
