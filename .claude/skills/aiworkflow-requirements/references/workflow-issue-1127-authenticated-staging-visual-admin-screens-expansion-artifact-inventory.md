## Lessons Learned

- **L-I1127-001**: 再利用基盤の横展開タスク（reuse-pattern expansion）では Phase 1 で「横展開候補 × current 実装状況の突合表」を作り、既実装済み（`/admin/tags` 等）をスコープ除外する。突合せずに元 issue の候補リストをそのまま実装すると、陳腐化した（既に done の）画面を二重実装する事故になる。`.claude/skills/task-specification-creator/references/phase-template-phase1.md` の `Reuse-pattern Expansion Inventory Gate` に昇格済み。
- **L-I1127-002**: staging 共有 D1 を持つ authenticated visual タスクの read-only 判定は「画面表示=危険」ではなく「mutation トリガーをクリックするか否か」で裁く。SubAgent は「フォーム/モーダル表示=副作用リスク」と過剰判定しがちだが、非クリックなら read-only GET のみで安全。route × mutation トリガー × ガード assertion（`getByRole("dialog").toHaveCount(0)` 等）の副作用境界判定表を Phase 11 に置くと正しく裁ける。`phase-template-phase11.md` の `Authenticated staging visual 横展開の read-only boundary` に昇格済み。
- **L-I1127-003**: `VISUAL_ON_EXECUTION` + `implemented_local_runtime_pending` の Phase 11 evidence inventory は `manual-test-result.md=present` / screenshot 5 行 `=n/a`（baseline 未生成）が compliance gate を通る正しい形。local spec 実装は完了したが実 capture は user-gated、という状態を「実画像捏造」せずに表現する。`phase12-compliance-check-template.md` に runtime pending inventory 例として昇格済み。
- **L-I1127-004**: 明確な implementation target（「5 spec 追加が必須」）を持つタスクを `spec_created` のまま閉じない。Playwright spec 5 本を同一 cycle で local 実装し `implemented_local_runtime_pending` へ昇格する。user-gated に残すのは staging capture / baseline / commit / push / PR だけに限定する。
- **L-I1127-005**: spec 正本ドキュメント（phase-5.md）のコメントに日本語混在が残っても、canonical 名（screenshot / selector / heading / route）が実装ファイルと一致していれば compliance gate・テスト動作・回帰検出には無影響。コメント文言差は drift として扱わず、canonical 識別子のみを整合性検証の対象とする（過剰な「CRITICAL」判定を避ける）。
